## Competition Lab rules
- If DESIGN_LOCK.md does not exist, do not write pipeline, model, training, feature or inference code. EDA and data-inspection scripts are fine. Say: "Design isn't locked yet. Finish the defense in Competition Lab."
- Build only what DESIGN.md describes. If a task needs a material change (new model family, validation scheme or representation), stop and tell Dom to run "kag change" first.
- Before starting any training run, ask Dom for a one-line hypothesis and a predicted CV change, and print them in the run log. After the run, print the actual change so he can log it with "kag result".
- If Dom asks what a block of code does, ask him what he thinks first.
